## v0.9.0

- Added `Complexity` stat (not yet incremented)
- Added Config on glyphs (so glyphs can have unique config values)
- Added `Impact` on glyph asset configs to remove magic numbers
- Added codec-registered Impact curves: PowerLaw, SphereVolume, RatioToDefault, Threshold (will add more as needed - again, removing magic numbers)
- Added per-slot `Impact` for multi-input cost scaling (Ensnare)
- Removed `AreaTax`/`computeAreaScale` - cost scaling now derived per-glyph via Impact
- Moved base cost compute onto `Glyph.computeBaseCost()` - `HexStats` only holds/tracks
- Migrated Force, Bolt, Gust, Area, Domain, Warp, Swap, Conjure, Phase, Erode, Fortify, Ensnare, Scale, Arc to Impact-based cost
- Reworked DebugGlyph output: wired slot shows linked glyphs (value, accuracy, speed, type); unwired shows full GIS variable map
- Made DebugGlyph translation-backed via `hexcode/debugGlyph.lang` templates with inline color/markup (chat `markupEnabled` enabled per node)
- Decoupled Complexity from Volatility: removed the dead `applyComplexity` seam that derived complexity from volatility spent
- Made Complexity a glyph-authored axis via opt-in `GlyphHandler.addComplexity(ctx, amount)`; no implicit accrual, glyphs are the source of truth
- Wired DebugGlyph `{complexity}` to read the live `HexStats` pool instead of the `0` placeholder
- Reworked glyph resource flow to simplify resource consumption
- Added automatic per-slot volatility cost: default `getVolatilityCost` = base cost x product of every per-slot `Impact` - global `Config.VolatilityImpact` is now override-only
- Added `Glyph.computeBaseCost(GlyphAsset)` overload to drop repeated asset lookups
- Ensnare: removed the damage input/dealing
- Aligned interaction tree of the experimental staff to be able to draw / cancel draw / cast
- mig: Moved large parts of the code to the proper locations / deprecated or removed many unneeded bits of code
- feat: Added `Exponential`, `Constant`, and `Linear` impact curves
- bug: Dropped the hardcoded construct drain fallback (configured constructs use the asset `DrainPerSecond` default)
- bug: Added `HexVar.copy()` and clone-on-write in `HexContext.setVariable` / `setDefaultVariable` so no two slots can alias the same mutable var
- Various bugfixes
- feat: Fleshed out the six element styles
- style: Centralized glyph style resolution in `VfxUtil.resolveModelId` / `resolvePrimaryColor` / `resolvePrimaryColorRaw` (context override then glyph asset); removed the duplicated per-glyph `resolveColor`/`resolveModelId` helpers and all eleven `DEFAULT_COLOR` constants
- style: Made `primaryModel` an overridable `HexStyleAsset` field (now carried by `applyOverride`) so context models win over the glyph asset model
- style: Routed Delay/Ensnare/Projectile/Shatter model spawns through style resolution; Glaciate and Conjure keep hardcoded structural models on purpose
- style: Defined `PrimaryColor`/`SecondaryColor` on every visual glyph asset (parenting `Essence_*`/`Self_Growth`/`Chaos_Void` where thematic), added `PrimaryModel` to Ensnare/Shatter
- style: Whitened every color-injected glyph particle spawner so the runtime-injected primary/secondary color is the sole color source (model trails, slot/effect, and pedestal particles left untouched)
- Migrated Shatter to a `ShatterConfig` leaf (default count/spread/speed/gravity, max count, shard ttl) - removed the in-handler magic constants
- Re-sourced Complexity accrual to flat `instantCost` (input scaling excluded); `getComplexity` reads `asset.getVolatility().getInstantCost()`, overridable via `Config.ComplexityImpact` fed instantCost - Domain now accrues its 10 tier weight, not the slot-inflated 200
- Moved the runtime Complexity pool (`currentComplexity`) off `HexStats` onto `HexContext` (branch-local); kept `initialComplexity` on `HexStats` as the configurable seed, `complexityMultiplier` stays as the Magic Power mult
- Added `HexContext.branch(int splitFactor)` that divides the copied Complexity by the fan width; bare `branch()` defaults to `/2` (safe-by-default dilution)
- Split Complexity at fan-out: authored `Next` forks and instant AoE (Area blocks/entities, Shatter shards) divide by exact K; persistent construct triggers (Conjure, Domain, Glaciate, Ensnare, Arc) halve per hit; `HexStatus` snapshot switched to `cloneState` (no split)
- Rebuilt the staff interaction system as decentralized reactive contexts: invariant client-predicted drawmode (`DrawCaptureComponent` presence = drawing, `HexDrawMode`/`HexDraw` do structural writes only) split from priority-arbitrated contexts (Flycasting 1 / Selecting 5 / Crafting 10) via `CasterComponent` + `ContextTransitionService` (single writer, higher priority preempts, preemption forfeits in-flight strokes)
- Reactive commit pipeline: `DrawRecognitionSystem` (presence-gated) finalizes ping-scaled shape windows and emits targeted `ShapeDrawnEvent` (raw `ShapeStructure`, cancellable); contexts resolve via stateless `GlyphResolver`, veto through `GlyphCommitEvent`, then place - no polled state machine
- Primary is one predicted `StatsCondition` gate on the new `InContext` entity stat: in-context routes to `HexContextPrimary` (input channel on `CasterComponent`, consumed by context tick systems), out-of-context executes the queued draft via `ExecutionConfig` reading the new non-persisted `ExecutionComponent`
- Pedestal interaction is now a thin `PedestalInteractEvent` hook; the builtin `PedestalContextHandler` owns eligibility, item->profile routing, session lifecycle, and context transitions; staff-unequip exits are per-context opt-in (Flycasting only), disconnect/death force-exit via `ContextForceExitEvent`
- Unwired the legacy state machine: dropped `HexTick`/`StateRouter` registrations, `HexMode`-family interactions, `HexcasterComponent`-on-connect, `StaffUnequipEvent`/`DrawingSlotLockEvent`/`HexcasterCleanupSystem`; `/state/` managers remain as dead reference; rewired SessionUtils/ImportInteraction/commands to the new components
- fix: draw mode never fired its enter/exit seam - `RefSystem` only dispatches on entity add/remove (Store.addEntity/removeEntity), never on component archetype transitions; `DrawModeLifecycleSystem` is now a `RefChangeSystem<EntityStore, DrawCaptureComponent>` (onComponentAdded -> DrawModeEnterEvent, onComponentRemoved -> trail cleanup + DrawModeExitEvent), so Flycasting actually enters and drawn glyphs spawn
- fix: the developer staff overrode `Interactions` (Primary -> Hexstaff_CastSpell) which bypassed the InContext gate, so left click always ran the execution flow; it also overrode `Tags.Family` to `Staff`, defeating hexstaff detection - both overrides removed so it inherits the template wiring
- fix: `CasterInventory.getHexStaffComponent` falls back to a default-style component for `HexStaff`-tagged items with no `HexStaffAsset` registry entry (registry is deprecated; the developer staff has no entry)
- Template staff now wires `Ability2 -> Hexstaff_Ability2` (flycasting force-commit channel)
- Added ECS event transparency logging to the counterspell diagnostics sub-plugin (`builtin/counterspell/eventListeners/*DiagnosticListener` for DrawModeEnter/Exit, HexContextChange, ShapeDrawn, GlyphCommit, ContextForceExit - disable the sub-plugin to silence) plus a context-enter rejection log in `ContextTransitionService`
- Removed the dead legacy interaction classes (`HexMode`, `HexModeExit`, `HexStateBranch`, `HexStateChange`, `HexHold`, `HexAbility`, `HexItemCondition`) and the now-unused `Hexstaff_CastSpell`/`Hexstaff_Drawmode` root interactions
- Finalized the staff migration: promoted the developer staff's `InteractionConfig` (Secondary main-hand hold priority 10 + creative use distance) and `EntityStatsToClear` baseline to `Template_HexStaff`; template `Tags.Family` is now `["HexStaff", "Staff"]` and every child staff's boilerplate `Tags` override (`Family: ["Staff"]`, which broke hexstaff tag detection) was removed so all staffs inherit the superset
- Developer staff pruned to its actual deltas (dev-tier StatModifiers, cosmetics, `Drawmode_Arcane` var); it inherits the full template `Interactions` map - Ability1 dispel included - since the item codec merges child maps over the parent's (`MapUtil.combineUnmodifiable`)
